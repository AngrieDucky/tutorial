Задача 1: Проектирование БД и Моделей

    Создать структуру базы данных и описать её в коде с помощью SQLAlchemy.

    Что делаем:
        1. Проектируем таблицы: users, applications (другие, при необходимости).
        2. Описываем связи.
        3. Пишем классы моделей для SQLAlchemy.
        4. Настраиваем connection_string и Создаём таблицы в БД.

Задача 2: Аутентификация (Вход и Регистрация)

    Реализовать логику создания пользователей и их входа в систему.

    Что делаем:
        1. Создаём формы регистрации и авторизации (HTML + WTForms).
        2. Пишем routes для обработки POST-запросов с этих форм.
        3. Реализуем хеширование паролей.
        4. Настраиваем сессии, чтобы пользователь оставался залогиненным.

Задача 3: Личный кабинет пользователя

    Дать пользователю возможность создавать заявки и видеть их список.

    Что делаем:
        1. Создаём страницу со списком курсов.
        2. Создаём страницу пользователя (доступно только после логина).
        2. Создаём страницу/форму/кнопку для создания новой заявки.
        3. Пишем логику сохранения заявки в БД с привязкой к текущему пользователю.

Задача 4: Система отзывов

    Добавить функционал обратной связи к заявкам.

    Что делаем:
        1. Модифицируем страницу просмотра заявок, добавив форму отзыва.
        2. Создаём модель Review в БД (с привязкой к другим таблицам).
        3. Пишем логику сохранения отзыва в базу данных с привязкой к конкретной заявке.

Задача 5: Панель администратора (Список заявок)

    Дать администратору возможность видеть все заявки пользователей.

    Что делаем:
        1. Создаём отдельный роут /admin с жесткой авторизацией (логин/пароль из ТЗ).
        2. Пишем роут, который достает из БД все заявки.
        3. Выводим их в виде таблицы на HTML-странице.

Задача 6: Управление статусами заявок

    Дать администратору инструмент для изменения статуса обучения.

    Что делаем:
        1. Модифицируем админ-панель: добавляем выпадающий список статусов («Новая», «Идет обучение», «Обучение завершено») для каждой заявки.
        2. Обрабатываем изменение статуса через форму.
        3. Обновляем поле status в таблице applications.
